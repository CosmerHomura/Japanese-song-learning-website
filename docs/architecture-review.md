# 架构评估（2026-09）

当前产品由 React/Vite 界面、Electron 壳、FastAPI 本地服务、SudachiPy/SQLite、本机 IndexedDB 与 Local Storage 组成。桌面版无需云端账号，适合本地优先的学习工具；目前更需要降低模块耦合与数据迁移风险，而不是整体换技术栈。

## 优先级 1：收紧桌面本地 API 的调用边界

状态：已实现桌面会话校验。付费 AI 路由在桌面模式下要求随机令牌，Electron 仅为允许列表中的请求经 IPC 附加令牌；网页开发模式继续由本机服务直接处理。后续正式发行前仍应做完整的安全审计，包括本机恶意进程、页面注入和系统代理等情景。

`desktop/main.cjs` 为设置、词典管理和付费 AI 请求附加随机管理令牌，`server/desktop_auth.py` 对付费路由校验。服务仍只监听回环地址；浏览器 CORS 是附加防线，不应代替桌面会话校验。

## 优先级 2：拆分两个“大文件”

状态：已开始渐进拆分。设置弹窗与整句解析已迁到独立 React 组件，LRC 时间逻辑、供应商注册表、计费归一化与桌面授权已有独立模块；歌曲库、练习和复习页面及部分后端路由仍在主文件中，后续可按页面逐步迁移。

`src/App.jsx` 约 1,500 行，交织歌曲库、练习、复习、设置、词典、导入、备份、计费与 API 调用。建议按页面/功能拆成 `LibraryPage`、`LessonPage`、`ReviewPage`、`SettingsDialog`，再用 `useSongLibrary`、`usePracticeSession`、`useAiSettings` 等 hook 承接状态与副作用。不要一次性重写；逐个抽出、逐个加回归测试。

`server/app.py` 约 1,200 行，混合路由、词典查询、分词、供应商模型目录、AI 调用、计费及封面检索。建议保留薄路由，逐步拆成 `services/annotation.py`、`dictionary.py`、`ai/providers.py`、`ai/catalog.py`、`ai/billing.py`、`artwork.py`；通过明确接口注入配置与缓存，避免跨模块全局状态。

## 优先级 3：统一学习数据的版本与事务

状态：已加入 v2 版本化学习快照。旧 Local Storage 记录会兼容读取，写入新快照成功后清理旧副本；旧版个人备份恢复会重建 v2 快照。歌曲音频仍在 IndexedDB，因此跨两种存储的原子事务尚未实现，需在独立迁移中处理。

歌曲音频/歌词仍在 IndexedDB，学习进度、注音、AI 记录和费用已合并为一个带版本的 Local Storage 快照。备份恢复处理了回滚，但跨存储更新仍难做到原子提交。后续可将歌曲与关联记录逐步集中到 IndexedDB；先补旧备份与真实升级场景测试，再改持久化层。分词修正宜使用稳定 token ID 或字符跨度，不用数组下标作为长期修正键，以免重新分词后错位。

## 优先级 4：为付费与打包路径补端到端验证

状态：已增加桌面授权、快照迁移与回退、LRC 时间工具的测试；真实 Electron 打包和无现成用户数据的安装冒烟仍需在干净 Windows 环境执行。

已有前后端单元测试，但缺少覆盖“导入 → 注音 → 修正 → 备份 → 恢复”和“设置 Key → 模型发现 → AI 用量/失败计费”的完整流程。优先以模拟供应商和临时用户目录做集成测试，另在干净 Windows 环境做 Electron 安装/便携版冒烟测试。发布前建立固定版本号、签名、产物校验与回滚流程；不要依赖开发机上的旧 EXE 验收。

## 建议实施顺序

1. 确定本地付费 API 授权边界并补安全测试。
2. 提取可独立测试的 AI/词典服务与前端设置模块。
3. 定义学习记录 schema 与迁移/备份兼容策略。
4. 按页面拆前端，最后补 Windows 打包和发布流水线。

后续可逐项验证后直接合并到 `main`，保持现有备份格式可恢复；不要在一次重构里同时替换 UI、存储和 API。
